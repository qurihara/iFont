# 4. 弱みと懸念

## 4.1 アプリの早押し度とタッチ時刻の関係を再現できない

**問題。** `main.tex:441-450` は早押し度を \(1-f(t)\) と定義する一方、`main.tex:892-894` は聞く役の早押し度を平均0.46、SD 0.21、タッチ時刻の中央値を第一音から218 msと報告している。これらの値が同じ正解取得タッチ集合から計算されたかが明記されていない。

同じ集合を指すと仮定すると、記載値とは整合しない。`main.tex:642` の \(\gamma=1/44\)、`main.tex:663-664` の \(x_0\le118\) ms、\(\beta_1\ge0.031/\mathrm{ms}\)、`main.tex:678` の \(\lambda\ge0.9\) を用いると、どの音声曲線でも

\[
f(218)\ge \frac{1}{44}+
\frac{0.9-1/44}{1+\exp\{-0.031(218-118)\}}
\simeq0.862
\]

となり、218 ms以降の早押し度は0.138以下となる。したがって、同一の観測集合で少なくとも半数が218 ms以降なら、平均0.46、SD 0.21という組合せは得られない。

**理由。** アプリは5つの貢献の一つであり、この値が異なるタッチ集合、参加者平均、未補正時刻、別の曲線、または実装上の変換から得られたのかによって結論が変わる。現状では正確さと再現可能性を判断できない。

**直し方。** 得点計算の擬似コード、用いた曲線が最尤値か縮約値か、時刻補正の順序、892行と894行の解析単位および対象タッチを明示する必要がある。また、両者が触れるまで待つのか、誤札、無反応、タイムアウトをどう扱うのか、`main.tex:553` の0.02という同時判定幅をどう定めたのかも記述する。そのうえで、同じ解析集合について時刻と早押し度の対応を再計算し、代表的な一試行の計算例を示すべきである。

## 4.2 認識曲線が適用される刺激と閲覧環境を十分に特定していない

**問題。** 視覚刺激は1/255から7/255程度という非常に低い不透明度域で識別率が変化するが、`main.tex:689-700` には書体、文字寸法、文字色、背景色、ブラウザ、画面輝度、表示ガンマ、および視距離が記載されていない。クラウド測定では更新周期だけを確認している。音声についても、`main.tex:581` はVOICEVOXの「話者1名」とだけ記し、話者名、バージョン、設定値、および後処理を示していない。

**理由。** この研究では刺激そのものが認識曲線を決める。特に低不透明度域はディスプレイ特性の影響を受けるため、`main.tex:306` の「閲覧環境の制約とも無関係」という表現は、提示された証拠より広い。実際の対戦画面とクラウド測定環境の関係も判断できない。

**直し方。** 使用した書体、CSS、色、寸法、描画式、ブラウザ、実験用画面、音声合成器の話者と設定、および音声ファイル作成手続きを記載する。クラウド環境の異質性を母集団として意図したのであれば、その母集団を推定対象として明記する。追加実験がない場合は、曲線が当該刺激と測定環境に依存することを主張範囲に反映すればよい。

## 4.3 曲線推定とブートストラップの再現情報が不足している

**問題。** `main.tex:641-647` は経験ベイズ縮約を説明するが、本研究の測定で用いた事前分布のハイパーパラメータと推定方法を示していない。候補版については参加者単位のブートストラップを詳述しているが、精密版の同時上限について、音声側と視覚側をどのように再標本化したかが分からない。各参加者が60試行を行うため、試行を独立とした区間と参加者単位の区間も区別する必要がある。

**理由。** \(\beta_1\) の縮約値は段階選択とアプリ得点に直接用いられる。推定手続きが再現できなければ、残差0.046、0.034および早押し度を監査できない。

**直し方。** ハイパーパラメータ、推定ソフトウェア、収束条件、縮約前後の値、クラスタリング単位、および各同時上限の再標本化手続きを記載する。新しい統計手法を必須とはしないが、参加者内相関を既存のブートストラップがどのように扱ったかを明示する必要がある。

また、`main.tex:194` は \(\lambda\) を「打ち切らずに提示したときの正答率」と定義するが、通し読み音声では `main.tex:656` の250 msが最長であり、完全提示条件を設けていない。ここでは「ロジスティック曲線の上側漸近値」と表現するか、完全提示条件との関係を説明する必要がある。

## 4.4 「公平」と「情報量」に関する一部の表現が操作的定義を超えている

**問題。** `main.tex:146` の「同じ情報量で競える」および `main.tex:441` の「どれだけ少ない情報で押したか」は、実際に測っている正答確率より広い概念を表す。トップ1正答率が等しくても、誤答の分布、確信度、個人差、および意味情報が同じとは限らない。

`main.tex:918` の「方向1と同じ効果を与えた」も、両条件が同等性幅に入ったこと以上を意味し得る。先着判定の再計算は、早押し度で判定されることを知って行動した同じ試行の事後解析であり、先着ルール下の行動を因果的に再現するものではない。

**理由。** この論文の長所は公平性を明示的に操作定義したことにあるため、その定義を超えた用語を使うと主張がかえって不明確になる。

**直し方。** 「情報量」を「当該母集団における正答確率」または「集団認識率」に置き換える。`main.tex:917-918` は、二つの方式がそれぞれ事前設定した同等性幅を満たしたことと、先着判定による記述的再計算で偏りが観察されたことに限定する。タイトルの「公平」は維持できるが、概要で操作的定義を明示するとよい。

ろう者や難聴者を含む追加実験は、現論文の採録条件とはしない。`main.tex:968-980` の限定を概要と結論でも一貫して維持すればよい。

## 4.5 投稿中のWISS論文の扱いが投稿規定に適合していない

**問題。** `main.tex:1004-1005` は「WISS 2026 投稿中」を通常の参考文献として掲げ、本文と再掲図の根拠として繰り返し引用している。

**理由。** 情報処理学会の原稿執筆案内では、参考文献は公表済みまたは採録済みのものを対象とし、投稿中の関連論文は編集側への別途申告を求めている。公開されていない文献を前提にすると、読者が基礎的方法を確認できない。本稿とWISS稿の重複範囲も査読者には確認できない。

**直し方。** WISS稿が採録済みになった場合は書誌を更新する。投稿中のままであれば参考文献から外して編集委員会へ別資料として申告し、本稿だけで理解できるよう必要な方法を記載する。再掲図と基礎データの重複範囲も編集側に明示する必要がある。これは二重投稿を断定する指摘ではない。

## 4.6 対戦実験の報告単位を明確にする必要がある

**問題。** `main.tex:827` の公平感評定を誰が回答したかが明確でない。両参加者が回答したなら、`main.tex:842` の「試合を単位」とする混合モデルとの関係を説明する必要がある。また、聞く役の勝数だけが示され、見る役の勝数と引き分け数が分からない。

**理由。** 評定の独立単位と階層構造は、標準誤差と検定結果に関係する。勝敗内訳は取り札数の同等性を補足する基本的な記述統計となる。

**直し方。** 回答者数、各試合で得た回答数、集約方法、欠測の有無、混合モデルの式、自由度、推定法、および変量効果の収束状況を記載する。全条件について聞く役勝ち、見る役勝ち、引き分けの内訳も示すとよい。

# 10. 査読者としての自信の度合い

査読判断に対する自信は **4/5** である。HCIおよびエンタテインメントコンピューティングにおけるシステム設計、利用者実験、心理測定曲線、混合モデル、同等性検定については十分な専門性があり、主張と証拠の対応、数値照合、および統計的解釈には高い自信がある。

音声知覚の詳細な生理・音響モデルについての専門性は中程度であり、著作権や商標権に関する `main.tex:618-625` の著者判断は本査読では評価していない。

最も判断に迷う点は、アプリの時刻と得点が異なる解析集合を指している可能性である。生データと実装コードがないため、誤計算と断定はできない。一方、同じ集合を指すなら数値が整合しないため、採録前の解消が不可欠である。WISS投稿稿も確認できないため、重複投稿とは判断せず、編集委員会による確認事項とした。関連研究の調査では一次情報を確認したが、国内外の全会議を網羅したことまでは保証できない。
