# 上毛かるたの測定(工程1〜2)の準備

timeFont を上毛かるた(44枚・すべて一字決まり)で公平な対戦に使うための、2つの測定の道具一式である。
計画の正本は https://claude.ai/code/artifact/cba249ac-2e92-4ed4-a271-9f28d19247d6 (第14版)と
cosense「iFont」の 2026-10-07〜08 の節にある。

- **測定A(音声の通し読み)** `audio_card.html` — 44札の読み上げを先頭から途中まで聞かせ、44択で札を当てる。札ごとにロジスティック曲線を当てはめ、レベル x0 と傾き β1 を得る。
- **測定B(文字の候補)** `visual_card.html` — 44札それぞれについて、1文字目がフェードで現れるアニメを速さ5段階(等比)で用意し、「1文字目がフェードで現れ、2文字目以降が読まれた時刻に現れる」提示を途中で打ち切って見せ、44択で当てる。

作成日 2026-10-08。ブランチ `prep-jomo-measure`。

## 札セットの形式(`cards_jomo.json`)

```
{
  "set_id": "jomo44", "name": "上毛かるた", "n_cards": 44,
  "grid": [["あ","い","う","え","お"], ..., ["わ","","","",""]],   // 回答ボタンの固定配置(""は空き)
  "cards": [
    {"id": "ひ", "kana": "ひ", "first_sound": "びゃ",
     "reading": "びゃくえかんのんじひのみて", "text": "白衣観音慈悲の御手",
     "moras": ["びゃ","く","え","か","ん","の","ん","じ","ひ","の","み","て"],
     "n_moras": 12, "n_moras_listed": 12},
    ...
  ]
}
```

- `kana` は表示する先頭のかな(回答ボタンの字)、`first_sound` は読みの1音目(モーラ)。ひ・ふ の札は読みが びゃ・ぶ で始まり、札のかなと異なる。
- `moras` は拗音を1モーラ、長音「ー」を1モーラとして分けた列。`n_moras_listed` は計画資料に記載の数(かな文字数で数えているため拗音を含む札で1大きい)で、照合用に残してある。
- `text` は読み札の本文(漢字かな交じり)。出典は群馬県の公式資料 https://www.pref.gunma.jp/uploaded/attachment/619787.pdf と https://www.kingofjmk.jp/%E4%B8%8A%E6%AF%9B%E3%81%8B%E3%82%8B%E3%81%9F%E5%85%A8%E6%9C%AD%E4%B8%80%E8%A6%A7/ 。
- **「ち」の札は現行の「力あわせる二百万」(にひゃくまん・12モーラ)にした。** 計画資料の読み「ひゃくきゅうじゅうまん」は1993〜2008年の版である。戻すときは `reading`・`text`・`moras` を書き換えて `synth_cards.py --only ち` を実行する。
- 別の札セットに差し替えるときは、同じ形式の JSON を用意し、`grid` に回答ボタンの配置を書く。ページとスクリプトは `grid` と `cards` だけを見る。

## 通し読みの音声の合成

### 設定(`synth_cards.py`)

- 話者 東北きりたん(VOICEVOX speaker 108・ノーマル)、VOICEVOX 0.25.2。音高は全モーラ B3(246.94 Hz)の一定音高(較正実験の1音刺激 audio1char と1モーラ目の条件をそろえるため)。`--pitch "B3,E4"` のようにモーラごとに変えられる。
- 時間構造: 第一音(1モーラ目)0.200 秒、本体(2モーラ目以降)0.270 秒/モーラ(子音と母音を同じ倍率で伸縮する一様の配り方)、語尾は最後のモーラ 0.27 秒のあとに長音モーラ(ー)を7つ(各 0.27 秒)足して **2.16 秒の母音(ん で終わる札は撥音)の持続**にした。1モーラの持続母音を 2 秒にすると VOICEVOX の F0 が揺れるので、`experiment/tools/build_karuta_samples.py` と同じく短い ー の列で作っている。
- 無声化の抑止: VOICEVOX が文脈で無声化する母音(audio_query の vowel が大文字)を小文字にして、全モーラを有声で読ませる。
- VOT の補正: 較正実験の1音刺激(`experiment/audio1char_votfix_B3_108.json`)と同じく、発話先頭の く・け・た・て・と の子音長を 2〜3 倍にした(1モーラ目だけ)。`--no-votfix` で止められる。
- 全体を1回で問い合わせるとモーラ数が合わない札(く「いでゆ」を デュ と読む、も「みょうぎさん」+ー)は、モーラごとに音素を問い合わせて組み立てる(長さと音高はどのみち全モーラ固定するので結果は同じ扱い)。
- 音量は A特性の実効値(本体の区間)を44札の中央値にそろえた(ピーク上限 0.85)。
- 音響的開始は `experiment/tools/build_onsets.py` と同じ規則(5 ms 枠の実効値が −63 dBFS を 15 ms 以上連続して超えた最初の点)で wav から実測した。
- **モーラ境界は実測ではなく計算値**である。VOICEVOX は音素長を 10.667 ms の格子に丸めるので、名目の長さを格子に丸めて積算した(較正実験で 0.2 秒のモーラが 202.667 ms になったのと同じ規則)。`mora_onsets_nominal_ms`(名目)と `mora_onsets_ms`(丸めたあと)の両方を書いてある。

### 実測(2026-10-08、44札)

- 第一音の長さ(音響的開始から2モーラ目の境界まで): 最小 175 ms(と)、中央値 196 ms、最大 206 ms。名目 200 ms に対して、子音の長い札(か・さ・し・な・ね・は・へ・ほ・み・む・り)が 192 ms、と(VOT 補正で子音 3倍)が 176 ms。
- 音響的開始: ファイル先頭から 50〜80 ms(先頭の無音 50 ms のあと)。
- 1札の長さ: 最小 5.21 秒(ろ)、中央値 5.51 秒、最大 6.85 秒(な・18モーラ)。本体(語尾を除く)は 0.2 + 0.27 × (モーラ数 − 1) 秒で、12モーラの札で 3.2 秒、18モーラで 4.8 秒。公開動画の実測(1札約6秒・本体3.5〜4.0モーラ/秒)に近い。
- 2モーラ目の境界(音響的開始から): 176〜206 ms。3モーラ目: 443〜476 ms。したがって打ち切り 450 ms では、ほとんどの札で2モーラ目までが聞こえる。
- 音量: 本体 −21 dBFS 前後、語尾 −26〜−32 dBFS、無音部 −80 dBFS 以下。

## ページの使い方

GitHub Pages の配信先は `https://unryu.org/iFont/`(`experiment/PRODUCTION.md`)。このブランチを main に取り込んで配信すると、次の URL になる。

- 測定A(本番): `https://unryu.org/iFont/experiment/jomo/audio_card.html?prod=1&wid=<作業者ID>`
- 測定B(本番): `https://unryu.org/iFont/experiment/jomo/visual_card.html?prod=1&wid=<作業者ID>`
- 点検モード(`?prod` なし): `https://unryu.org/iFont/experiment/jomo/audio_card.html` 、`.../visual_card.html`

手元で動かすときは、リポジトリの根で `python3.11 -m http.server 8787` を実行し、
`http://localhost:8787/experiment/jomo/audio_card.html` を開く(フォントを `../../fonts/` から読むので、根から配信する)。

### 本番モード(`?prod=1`)

既存の6ページと同じ配管(`prod_common.js`)で、冒頭に同意画面、各試行を GAS に送信、最後に完了コードを出す。
`prod_common.js` の `SUBMIT_URL` は **空のまま**なので、いまは送信を飛ばす。デプロイのときは
`gas/code.gs`(`handleJomo` を追加済み)を Apps Script に貼り直して新しいデプロイを作り、その `/exec` URL を `SUBMIT_URL` に貼る。
`ANSWER_KEY` は不要(正誤は端末側で決めて送る)。

同意画面の文面は `prod_common.js` の `consentScreen` で、6ページと共通の「かな1文字の分かりやすさを測る研究」のままである。札当て課題向けに文面を変えるなら、そこに課題別の文面を渡せるようにする(未対応)。

### 点検モード(`?prod` なし)

研究者が挙動を確かめるためのもので、記録は送信せず、各問のあとに正解と打ち切り・実提示時間を表示し、最後に結果 JSON をダウンロードできる。URL パラメータ:

| パラメータ | 意味 |
|---|---|
| `?n=10` | 本番の試行数を変える(統制試行は n/9) |
| `?cut=120` | 打ち切りを1つの値に固定する |
| `?card=あ,か` | 出題する札を限る |
| `?speed=0` | (測定B)速さの段階を固定する(0=最も遅い … 4=最も速い) |
| `?feedback=0` | 各問のあとの正解表示を止める |

### 流れ

同意 → 教示(3〜4ページ。44札の一覧表を含む) → 練習3問(各問のあとに正解を表示) → 本番72問 → 完了コード。
本番モードでは既存ページと同じく、練習のあとは正解を表示しない。

## 打ち切り時点と出題の設計

- **打ち切り時点(8点)**: 第一音の音響的開始から 40, 80, 120, 160, 200, 260, 340, 450 ms(`jomo_common.js` の `CUTS_MS`)。1モーラ目(約 0.2 秒)の中に 6 点、2モーラ目に 2 点。測定Bも同じ8点(文字側は1文字目のフェード開始が原点)。
- **統制試行**: 1000 ms(3モーラ目まで聞こえる・見える)。参加者の除外の判定に使う。
- **1人あたり 72 問**: 段階つき 64 問(8時点 × 8)+ 統制 8 問。札は 72 問に均等に配る(各札 1〜2 回)。計画の「44札・8時点・各30試行」には、測定Aで約 165 名、測定Bで速さ5段階ぶん約 825 名が要る(1名あたり 64 問の段階つき試行を 44 × 8 = 352 セルに配るので、1名でセルあたり 0.18 試行)。
- **測定Bの速さ5段階**: フェード(不透明度が 0 から 1 まで線形に上がる)の所要時間を `fade_ms = 600 × 10^(−k/4)`、k = 0..4 → **600, 337, 190, 107, 60 ms** とした(等比・隣接比 0.56)。音声側の β1 ≈ 0.06〜0.6/ms(10倍の幅)に対応づける設計で、どの段階がどの β1 に当たるかは測定の結果で決まる。速さは**参加者内の要因**で、5段階 × 8時点 = 40 セルに均等に配ってから順序を混ぜる(1名あたり各セル 1〜2 問)。
- **測定Bの提示**: 読みのモーラ列を枠(400 × 120 px)に左から並べ(9モーラを超える札は2行)、1モーラ目は時刻 0 からフェード、2モーラ目以降は `cards_audio.json` の `mora_onsets_rel_ms`(音響的開始を原点にした音声のモーラ境界)の時刻に一括で現れる。cut_ms で枠を白に戻す。字形は BIZ UDGothic(リポジトリ同梱)を canvas の fillText と globalAlpha(透明度)で描く。ぼかしと違って WebKit でも正しく出る。1モーラ目の表示は読みの1モーラ目(ひ の札は「びゃ」、ふ の札は「ぶ」)で、札のかな(ひ・ふ)ではない。これは**栗原さんの確認が要る決め事**で、変えるなら `visual_card.js` の `drawFrame` で `card.moras[0]` を `card.kana` に替える。
- **開始の仕方**: どちらも自己ペースのクリック開始。測定Aは「ピッ」の 300 ms 後に音声、測定Bは「+」の注視点 300 ms 後に文字。開始時刻が予測できるので、反応時間の起点(`rt_ms`)が定まる。「もう一度」で再提示でき、再提示の回数は `replays` に記録する。
- **回答**: 44札の先頭かなを五十音の格子(10行 × 5列、や行・わ行は空き)に並べたボタン。固定配置。各ボタンに読みの冒頭4モーラを小さく添える(ひ=びゃくえか、ふ=ぶんぶく)。

## 記録の列(GAS `jomo_trials` シート。点検モードの JSON も同じ名前)

`ts, participant_id, worker_id, completion_code, task(audio_card|visual_card), set_id, version, trial_index, stimulus_id(札のかな), cut_ms, is_catch, response_char, correct_char, correct, rt_ms, replays, n_choices(44), speed_idx, fade_ms, actual_ms, actual_frames, first_mora_ms, ua, dpr, screen, touch, refresh_hz`

- `actual_ms` / `actual_frames`(測定B): 最初に描いたフレームから消したフレームまでの実時間と描画フレーム数。名目の cut_ms は画面のリフレッシュ周期に量子化されるので、名目との差を見る。
- `first_mora_ms`(測定A): その札の第一音の実測の長さ。
- `ua`: WebKit 端末の判定などに残しておく(既存の注意事項と同じ)。

## 分析の手順

```
python3.11 experiment/jomo/analyze_card.py <jomo_trials を書き出した csv/tsv か、点検モードの json ...> --out <出力先>
python3.11 experiment/jomo/analyze_card.py --simulate 150 --task audio  --out /tmp/sim_audio    # 擬似データで回復を確かめる
python3.11 experiment/jomo/analyze_card.py --simulate 750 --task visual --out /tmp/sim_visual
```

- 本命試行は is_catch が偽の試行。参加者の除外は「同じ答えが 30% 以上」「統制試行の正答率が 50% 未満」で、除外した参加者と理由は `summary.json` に書く。
- モデルは p(x) = 1/44 + (λ − 1/44) / (1 + exp(−β1 (x − x0)))。床は 1/44 に固定、上限 λ は自由(主解析)と 1 に固定(比較用)。二項分布の最尤推定(多数の初期値から L-BFGS-B)。β1 の 95% 区間はプロファイル尤度。β1 の探索範囲は 0.001〜1.0/ms で、上限に張り付いた札は「階段状」の印を付ける(打ち切り間隔 40 ms では区別できない)。
- 出力は `curve_points.csv`(札 × 速さ × 打ち切りの試行数と正答率)、`fit_table.csv`(札 × 速さの x0・β1・λ・区間)、`summary.json`(速さの段階ごとの β1 の分布と R)、`fig_curves.png`(札ごとの曲線)。
- 擬似データでの回復(150 名・音声・真の β1 を 0.03〜0.5/ms に一様対数分布): x0 の RMSE 7.6 ms、log10 β1 の RMSE 0.40(2.5倍)、95% 区間の被覆 86%。β1 が 0.3/ms を超える札は打ち切り間隔(40 ms)より遷移が短く、点推定が上限に張り付く(44札中5札)。これは較正実験の β1 の推定(`project/beta1_range/`)と同じ限界で、K の設計では「階段状の札は最速の段階に丸める」扱いになる。

## 動作確認の結果(2026-10-08)

- Claude 自身のブラウザ(Chromium 系)で、`http://localhost:8787/experiment/jomo/audio_card.html?n=4` と `visual_card.html?n=4&cut=450&speed=0` と `audio_card.html?prod=1&wid=testworker` を開いて確かめた。
- 測定A: 44 wav の読み込みと復号(進捗バー)、同意 → 教示 → 練習 → 試行の流れ、再生ボタンで合図音1回+刺激+合図音2回の4ノードが予約されること、40 ms の切り出しが 40 ms(ピーク 0.35)になること、回答のあとの正解表示と記録(stimulus_id, cut_ms, response_char, correct, rt_ms, replays, first_mora_ms)を確認した。
- 測定B: フォントの読み込み、t = 300 ms で「な」が半透明・「か」が不透明になる描画、t = 1000 ms で「びゃくえか」が出る描画、本番モードの同意画面、記録(speed_idx, fade_ms, actual_ms, actual_frames)を確認した。
- 確かめていないこと: **実機の 60 Hz での描画フレーム数**。確認に使ったブラウザのプレビュー面は requestAnimationFrame が約 5 Hz に絞られており(refresh_hz = 5)、1000 ms の提示が 2 フレームになった。普通のブラウザの前面タブなら 60 フレーム前後になるはずで、点検モードの各問のあとに「実提示 ○ ms / ○ フレーム」が出るので、そこで確かめられる。Safari(WebKit)での表示と、スマートフォンでの格子の見え方も未確認。音声は耳で聞いていない(数値での確認のみ)。
